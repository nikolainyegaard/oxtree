# Gotchas and decisions

Dated notes on things that look wrong until you know why, and on dead ends. Add to this the moment something non-obvious is decided.

## 2026-10-21

- **Sizes are allocated sizes only.** The tree stores `st_blocks * 512` per node and nothing else, which is what the views show (QDirStat shows allocated size in the tree too). Sparse files therefore look small, and the cache writer emits allocated size in the size field. Writing cache version 1.0 instead of 2.0 is deliberate: 2.0 wants uid, gid and permissions, and the arena does not keep uid and gid.
- **Children are born sorted.** `Tree::build` computes subtree totals from the records before allocating nodes, so every directory's child block is written largest first and nothing ever sorts for the treemap. Sorting by another column in the tree view sorts a copy of one directory's indices when the rows are rebuilt.
- **The `<Files>` dot entry exists only when a directory has both files and subdirectories**, as in QDirStat. Its path is its parent's path; `Tree::path` skips it.
- **Scan completion used to be late by up to 333 ms** because the progress loop slept for the whole reporting interval before checking. It now polls every 5 ms and reports every 333 ms. The benchmark showed 716 ms for a scan that takes about 110 ms.
- **Excluded directories and mount points are leaf nodes**, kind `UnreadDir` or `MountPoint`, so the user sees they were skipped. Btrfs subvolumes have their own device id, so on this laptop scanning `/` stops at `/home` and reports 30 GB while `/home` alone is 350 GB. QDirStat behaves the same with its default `CrossFilesystems=false`. Crossing is on by default since 2026-10-22 (`OXTREE_CROSS_FILESYSTEMS=0` turns it off): a boundary is entered only when the mount table says it is local storage: kernel tables (device without a slash, or under /dev, /proc, /sys), network mounts (nfs, cifs, smb, sshfs, 9p, afs) and autofs stay leaves; a boundary with no mount entry, such as a nested btrfs subvolume, is entered. Rules from QDirStat's `MountPoints.cpp`, in `crates/native/src/mounts.rs`.
- **Cleanups and trash rescan the whole tree** for any refresh policy other than NoRefresh, but nothing on screen changes until the new tree lands: the old tree and texture stay, and the selection, expanded directories and treemap zoom are carried over by path (`Tree::find`, `find_nearest`) because every node id changes with the arena. A subtree rescan spliced into the arena is the upgrade if scans ever get slow enough to notice. Marked `ponytail:` in `app.rs`.
- **Local time is one offset from `date +%z`**, read once at startup. A timestamp on the other side of a daylight saving change shows an hour off. Pulling in a tz database parser for a file list did not seem worth it.
- **Hard links are counted once per link.** A file with two names inside the scanned tree is counted twice. QDirStat tracks `(dev, ino)` for `nlink > 1`; that is the fix if someone wants it.
- **No file dialog crate.** Open Directory has a text field plus Browse, which runs `kdialog --getexistingdirectory` or `zenity --file-selection --directory` as a child process. Cache files are entered as paths.
- **Treemap rebuilds run on one worker thread at a time, every frame during a resize.** A 200 ms settle delay like QDirStat's DelayedRebuilder exists behind `OXTREE_REBUILD_DELAY_MS` and is off by default: the per-frame cost measured at about 120% of one core only while dragging, and the instant rebuild is the point. The previous texture is drawn unstretched and anchored top left while a job runs; the first version stretched it, which distorted every tile and looked wrong. Results from stale generations (zoom changed meanwhile) are dropped.
- **Clippy's `indexing_slicing` is denied workspace-wide.** The arena uses `get()` everywhere and the pixel loops use `as_chunks_mut::<4>()`. The bounds checks cost the same as the ones `[]` would do; the difference is that a bad index returns a default instead of aborting the app.
- **The release profile uses `panic = "abort"`.** With every panic path denied by clippy there is nothing to unwind, and abort keeps the binary smaller.

## 2026-10-22, the window move flicker, solved

- **The clear colour is opaque on purpose** (`Shell::clear_color` in `apps/oxtree/src/main.rs`). eframe's default clear colour is `(12, 12, 12, 180)`: 70% alpha, so that a window switched to transparent looks transparent at once. OxTree's window is not transparent, but on Wayland Mesa still hands it ARGB8888 buffers, and winit declares the surface fully opaque. KWin therefore never repaints what is behind the window, while the GL blend still happens with alpha 0.7 against whatever the output buffer held before: the previous frame. The tree area and the treemap panel use `Frame::NONE` and paint no background, so 37% of the window's pixels carried alpha 180 (measured with the `--screenshot` alpha line). Reported upstream as emilk/egui#8761 with the fix in PR #8765 (both native backends force alpha 1 for non-transparent viewports); once a release contains it the override here can go. Symptoms, all of them: content at the window's previous position bleeding through for a frame while moving; the wallpaper showing inside the window; a hidden treemap fading out in a choppy animation (each frame blends 70% over the last, so the stale content decays by 0.3 per frame across KWin's two or three output buffers); and with KWin's partial repaints, stale regions beating on another window's refresh for seconds. R365 never showed it because every region of its window is painted by a filled panel. XWayland never showed it because X11 windows are composited opaque. Making the surface transparent hid it because KWin then repainted the wallpaper behind the window and the 30% see-through went unnoticed on a dark background. Not the display, not PSR, not overlay planes, not buffer age; two kernel parameters and three KWin switches were tried before the alpha of the frame was measured.
- **Lesson for the next one:** when a Wayland window shows other content through it, check the alpha of the rendered frame first. `--screenshot` prints the minimum alpha and the count of translucent pixels; it must say `min 255`.
- **Camera recordings of a moving window are not evidence of a display fault.** A phone's rolling shutter samples the top and bottom of the frame on different refreshes, so a moving window shows as a band with a ghost, title bar included.
- **A Spectacle window recording cannot show position glitches.** It records the surface content. Use a full-screen recording when the question is where things are on screen.

## 2026-10-22, search

- **The File View list is built on a worker thread** (`request_file_view`, `pump_file_view` in `app.rs`). The first version built it on the UI thread per keystroke, which froze the text field for the length of the build, up to a second on a home directory in path mode. Now the old rows stay until the new ones land, results carry a generation and stale ones are dropped, and keystrokes during a build coalesce into one more build. The search box itself is never blocked.
- **Substring terms compare in place.** `contains_ignore_case` scans ASCII names with `eq_ignore_ascii_case` and only lowercases non-ASCII names, which are rare; the per-node `to_lowercase()` it replaced was most of the name-mode cost.

- **Fonts: one bundled face plus the system's.** egui's `default_fonts` bundles Hack, Ubuntu Light and an icon font, and since 0.37 no emoji font, so Japanese and emoji in file names rendered as boxes. OxTree now registers Ubuntu Light for both families and the icon font by hand (`fonts()` in `main.rs`) and turns on eframe's `system_fonts`, which loads the machine's fonts on demand for anything else. Net effect on size: Hack out, the provider in, about 300 KB larger; the trade was taken for the names. The first frame did not move. A file name in a script with no font installed still shows boxes, which is the system's state, not ours.
- **Development tools live behind the `diagnostics` Cargo feature** (`apps/oxtree/src/diagnostics.rs`, `src/bin/bench.rs`, the `screenshot` and `stats` fields in `OxTreeApp`). They cost nothing in bytes worth measuring, about 300 lines in total, but they are not the app, and `main.rs` should read as the app. A plain `cargo build --release` has none of them; the gate in the CLAUDE.md runs clippy and the tests with and without the feature.
- **eframe's `clipboard` feature is on by name.** The dependency disables default features to keep wgpu and accesskit out, and the first cut forgot clipboard along with them. Copy Path still worked because `Context::copy_text` goes out through the same crates only for writing; reading the clipboard for Ctrl+V needs the feature. Any future trimming of the eframe feature list must keep it.

## 2026-10-22, startup

- **Starting the scan before the window delays the window.** The walk is syscall-bound on every core, so the single-threaded window setup (EGL init, shader compile) runs slower beside it: the empty window appears about 40 ms later and the tree about 90 ms earlier. Tried as the default for one commit and reverted the same day: the window's own latency is what a launch feels like. The early start and its switches were then removed rather than kept; the measurements are in performance.md. Fewer early threads do not help: at 7 the tree gain halves, at 4 it is gone.
- **Measure in the performance power profile.** The same binary starts in 34 ms in the performance profile and 86 to 90 ms in the balanced profile on battery, and scans /usr in 110 ms against 250 ms. Half an afternoon went into a "regression" from 30 to 90 ms that was the laptop being unplugged and moved to the sofa. Check `/sys/firmware/acpi/platform_profile` before trusting any timing.
- **The dlopen figure in the startup map was measured with a one-off script outside the app**, not with anything in the repo, which is Rust only.

## 2026-10-22, root

- **Rescan as Root is a second process that replaces the first.** Linux cannot raise a running process's privileges, so File, Rescan as Root runs `pkexec env WAYLAND_DISPLAY=... DISPLAY=... OXTREE_CONFIG_DIR=... oxtree PATH`. pkexec clears the environment, so the display variables are passed explicitly, and `WAYLAND_DISPLAY` is made absolute because root's `XDG_RUNTIME_DIR` is not the user's. The root instance reads the user's config through `OXTREE_CONFIG_DIR` and `save_cleanups` refuses to write as root, so no file ends up owned by root (QDirStat fixes ownership after the fact instead). The root instance touches `$XDG_RUNTIME_DIR/oxtree-root-PID` after its first frame and the starting instance closes when it sees the file, so the user sees one window hand over to the next; a dismissed or refused dialog (pkexec exits 126 or 127) leaves the first window as it was. The child's stdout and stderr are null, not pipes: once the parent is gone a pipe would be closed and the child's first print would fail. The polkit dialog shows a generic message unless `packaging/com.github.nikolainyegaard.oxtree.policy` is installed and the binary is at `/usr/bin/oxtree`, which is what the action file's `exec.path` names. Tested by the user on KDE Wayland; untested on GNOME and X11.

## 2026-10-22, the parity batch

- **Free space only for mount points.** The status bar and the details panel show the volume's free space for every scan, but the `<Free Space>` tree row and the treemap strip appear only when the scanned directory is a mount point (`MountTable::at` finds it). A scan of /usr on a 1 TB volume would otherwise be a 3% sliver next to a 97% grey strip, which says nothing.
- **Hard links share their size.** `blocks * 512 / nlink` per link rather than "first link wins", so the tree is the same on every run of a parallel walk. A file whose other links live outside the scanned directory shows smaller than it is; QDirStat has the same property.
- **File type categories come from a plain file.** The category of an extension is whatever the categorizer says for one file of that type; symlinks are skipped as the sample, since every extension with a symlink among its files would read Symbolic Links. Man page sections (`.1`, `.2`) land under Libraries because `*.so.*` matches them; harmless.
- **Tile names only on layout leaves.** A directory's name over its children would collide with their names, so a tile gets a name only when the next tile in the layout is not its child. The root of the map gets none either. Names cost one text shape per labelled tile per frame; the View menu toggle exists for the day someone has a 4K map full of them.
- **A cleanup over a selection runs per item.** QDirStat runs the command once per selected item; OxTree queues the rest in `cleanup_queue` and starts the next from `pump` when the output window reports the previous one finished, with the rescan after the last. One output window, so only the last item's output stays visible.
- **Column widths include their padding.** `Columns::text_right` is the right edge minus 4 points; the percent bar runs between the paddings. The three tables share `columns::header`, which also owns the drag handles; a dragged width is a plain `f32` in `OxTreeApp`, reset by the Reset button and lost with the window until the settings file exists.
- **The Reset button is an eraser, not an arrow.** A circular arrow reads as Refresh, which F5 already is; the eraser says "clear". Painted, like the tree icons.

## 2026-10-23, Windows and macOS

- **The MFT reader needs no `unsafe`.** `std::fs::File::open(r"\\.\C:")` opens the raw volume with the default share mode, and reads work as long as offset and length are whole sectors; the reader only ever reads whole clusters, and the boot sector as 4 KiB. The `unsafe_code = "forbid"` lint stays.
- **MFT records are streamed, not loaded.** `$MFT` is a gigabyte on a volume with a million files; the reader keeps one `Entry` per record (about 80 bytes plus the name) and 4 MiB of buffer. Extension records (`base_record != 0`) write their `$DATA` size into the base entry whichever order they come in, so sizes are only ever set, never reset.
- **Resident files count their bytes.** A file small enough to live inside its MFT record has no allocation of its own; its value length is used so tiny files are not all zero. WizTree shows the same figure as "size".
- **The NTFS test image** is `crates/native/testdata/ntfs.img.xz`, 16 MiB made with `mkntfs -F -Q`, mounted through `udisksctl loop-setup` and `udisksctl mount` (a desktop user may; plain `ntfs-3g` may not), filled with directories, a hard link, a symlink and 400 small files, then zero-filled with `dd if=/dev/zero of=fill` and `rm fill` before unmounting so it compresses to 98 KB. `xz -9` on it; gzip stays three times larger. The test skips where `xz` is not on the path.
- **Windows always runs elevated.** The manifest in `packaging/oxtree.manifest` is embedded through `build.rs` with `/MANIFEST:EMBED /MANIFESTUAC:NO /MANIFESTINPUT:` (without `/MANIFESTUAC:NO` mt.exe fails with c1010001 because the linker's default fragment says asInvoker), so `root::is_root()` is true there and Rescan as Root is never offered. `write_ini`'s "never write as root" guard is Unix-only for that reason.
- **No OpenGL on GPU-less Windows.** Windows 365 and other virtual desktops expose only Microsoft's OpenGL 1.1 and egui_glow needs 2.0, so the window never opens. The release ships a separate zip with Mesa's llvmpipe (`opengl32.dll` plus `libgallium_wgl.dll`, 62 MB unpacked) from mesa-dist-win; dropped next to the exe, Windows loads it before the system one. Never put it in the main zip: it would override every real driver. `main.rs` shows the hint in a PowerShell message box since the GUI subsystem has no stderr.
- **The GUI subsystem swallows stdout on Windows.** `--export -` prints nothing; the diagnostics build keeps the console subsystem for its prints.
- **The fixed-size Windows walk is the fallback, not the product.** `meta.rs` rounds `file_size` to 4 KiB and counts one link per file, because `std` has no allocated size or link count without `by_handle` calls. Only exFAT, network shares and a failed volume open get it.
- **Local cross-checks are not possible on Fedora's rustc.** The system toolchain has no `rustup target add`; the `ports` CI job is the compile check for both targets.

## Pinned, ports

- **Windows needs the MFT reader or nothing.** Built 2026-10-23, see above. Decided 2026-10-22: a Windows build without reading the NTFS Master File Table would be slower than WizTree by an order of magnitude and is not worth shipping. The reader is its own project; see the Ports section of `docs/wiztree-parity.md`. macOS is a native-crate branch and could go first.

## 2026-10-22, settings

The settings file landed: `~/.config/oxtree/settings.conf`, read by `oxtree_core::settings` through the INI parser, written when the Preferences dialog closes and on exit. The pinned items became keys; what was decided then still holds:

- **Cross filesystems** is `[DirectoryTree] CrossFilesystems`, default true. Off is the administrator's view, which filesystem is full. A per-physical-disk rule was considered and rejected: a /home on a second drive would be cut off again, and LVM, mdraid and LUKS make "same disk" ambiguous. The mount classification is not a setting. `OXTREE_CROSS_FILESYSTEMS` is gone from the app; the benchmark binary still reads it for timing runs.
- **Update check** is opt-in: `[Updates] CheckAutomatically=false`, `CheckIntervalDays=7`, `LastCheck`. A check is one GET of the GitHub releases API through `curl` as a child process, the tag compared with the workspace version, a line in the dialog with a link to the release page and one status bar line when a newer release exists. No download, no install, no request of any kind while the toggle is off and the button is not pressed. `release_tag` finds `"tag_name"` by string search; no JSON crate for one field.
- **Treemap rebuild delay** is `[Treemaps] RebuildDelayMillisec`, default 0, 200 the QDirStat-like value for slow machines; `OXTREE_REBUILD_DELAY_MS` is gone. The 120 Hz cap stays a constant.
- **Every value falls back alone.** A bad or out-of-range value in the file is replaced by its default and the rest of the file is kept; column widths are taken only when their count matches the table, so a file from before a column was added does not misalign anything.
- **Size decimals is a process-wide atomic** in `format.rs`, because `format::size` is called from every view and the benchmark; threading a parameter through would touch forty call sites for one setting.
- **Window size comes from `screen_rect`**, not the viewport's `inner_rect`, which Wayland leaves empty.
- **Update Now goes through the package manager, never around it.** A package installed from a repository is upgraded with `dnf upgrade` or `apt-get install` of the package name; one installed from a file gets the next file from the release, verified with `sha256sum` against the release's SHA256SUMS, and handed to `dnf install` or `apt-get install`. Both run through `pkexec`, the desktop's prompt and the session's polkit rules, as Rescan as Root does; replacing `/usr/bin/oxtree` by hand would leave the package database wrong. The AppImage is the one copy that swaps itself: the new file is staged beside it and renamed over, and the running copy keeps its unlinked file. The tarball gets the link. `dnf repoquery --installed --queryformat %{from_repo}` says `@commandline` for a file install, which is how the two package cases are told apart; apt's `apt-cache policy` lists a repository line for the installed version. After an install `LastInstalled` records the tag, so a release whose binary reports an older version than its tag is not offered in a loop. The downloaded package lives in `~/.cache/oxtree` until installed. No file of this feature exists for releases before 0.2.0, which have no SHA256SUMS; Update Now from 0.1.1 says the checksum did not match, and the link is the way.
- **Settings are state, not a struct the views read.** `OxTreeApp` keeps the fields it always had; `Settings` is the transport between them and the file (`apply_settings`, `to_settings`). The dialog binds to the fields directly, so a change shows at once and the file catches up when the dialog closes.

## Dead ends from the spike (2026-10-21)

- io_uring batched statx: slower on a warm cache in every published measurement, because the kernel hands statx to io-wq threads.
- Custom getdents and statx calls: std already stats relative to the directory fd and uses `d_type`.
- Reading filesystem metadata tables directly (the WizTree approach): no Linux equivalent of the MFT; ext4 inodes have no names, btrfs tree search needs root.
- The REBUILD_STOPWATCH comparison against QDirStat's treemap build time was never run; it needs a Qt source build.
